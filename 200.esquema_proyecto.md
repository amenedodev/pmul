# Estructura de una aplicación Android (Java con Android Studio)

Cuando creas un proyecto en Android Studio, se genera una serie de carpetas y archivos. Cada uno tiene un papel concreto. Este documento explica para qué sirve cada parte y cómo encajan entre sí.

> Al crear el proyecto, elige una plantilla basada en *Views* (por ejemplo, *Empty Views Activity*) y selecciona **Java** como lenguaje. Las plantillas de Jetpack Compose usan Kotlin y una estructura de interfaz distinta.

## 1. Proyecto y módulos

- Un **proyecto** es todo el espacio de trabajo de la aplicación: código, recursos, pruebas y configuración de compilación.
- Un **módulo** es una unidad dentro del proyecto, con sus propios archivos fuente y su propia configuración de compilación. El módulo de la aplicación se llama **`app`** por defecto. Un proyecto puede tener varios módulos (por ejemplo, módulos de biblioteca).

## 2. Dos formas de ver el proyecto

Android Studio ofrece dos vistas en la ventana *Project*:

| Vista | Qué muestra |
|---|---|
| **Android** (predeterminada) | Agrupa los archivos por tipo: `manifests`, `java`, `res` y `Gradle Scripts`. **No coincide** con las carpetas reales del disco, pero es más cómoda. |
| **Project** | Muestra la estructura real del disco, incluidas carpetas ocultas como `build/`. |

## 3. Esquema general

Así se ve en la vista **Project** (en disco):

```
MiApp/
├── app/                              ← módulo de la aplicación
│   ├── build.gradle(.kts)            ← configuración del módulo
│   ├── src/
│   │   ├── main/                     ← lo que se incluye siempre en la app
│   │   │   ├── AndroidManifest.xml   ← manifiesto
│   │   │   ├── java/                 ← código Java
│   │   │   │   └── com/example/miapp/
│   │   │   │       └── MainActivity.java
│   │   │   ├── res/                  ← recursos (imágenes, textos, pantallas…)
│   │   │   │   ├── drawable/
│   │   │   │   ├── layout/
│   │   │   │   ├── mipmap-*/
│   │   │   │   └── values/
│   │   │   └── assets/               ← archivos que se incluyen tal cual (opcional)
│   │   ├── test/                     ← pruebas locales (JUnit)
│   │   └── androidTest/              ← pruebas en un dispositivo
│   └── build/                        ← resultado de compilar (se genera solo)
├── build.gradle(.kts)                ← configuración común a todo el proyecto
├── settings.gradle(.kts)             ← lista de módulos del proyecto
├── gradle.properties                 ← opciones de Gradle
└── local.properties                  ← ruta al SDK de tu equipo (no se sube a Git)
```

En la vista **Android** esto se reduce a tres grupos dentro de `app` más uno aparte:

- **manifests** → `AndroidManifest.xml`
- **java** → el código fuente
- **res** → los recursos
- **Gradle Scripts** → todos los archivos de configuración de compilación

## 4. El código Java (`java/`)

Aquí está el código de la aplicación, organizado en **paquetes** (por ejemplo, `com.example.miapp`). La plantilla genera una clase `MainActivity`, que es la primera pantalla.

```java
package com.example.miapp;

import android.os.Bundle;
import android.widget.TextView;
import androidx.appcompat.app.AppCompatActivity;

public class MainActivity extends AppCompatActivity {

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);

        // Carga la pantalla definida en res/layout/activity_main.xml
        setContentView(R.layout.activity_main);

        // Busca un elemento de esa pantalla por su id y le pone un texto
        TextView texto = findViewById(R.id.texto);
        texto.setText(R.string.saludo);
    }
}
```

Dentro de la carpeta `java/` suelen aparecer tres paquetes con el mismo nombre: el de la app y dos para las pruebas (`androidTest` y `test`).

## 5. El manifiesto (`AndroidManifest.xml`)

Es el "documento de identidad" de la aplicación. Toda app debe tener uno, y le dice al sistema Android, a las herramientas de compilación y a Google Play lo esencial sobre ella. Declara:

- **Los componentes** de la app: cada actividad, servicio, receptor de difusiones y proveedor de contenido necesita su elemento (`<activity>`, `<service>`, `<receiver>`, `<provider>`). Si no se declara, el sistema no puede iniciarlo.
- **Los permisos** que la app solicita (`<uses-permission>`).
- **Las características** de hardware o software que necesita (`<uses-feature>`).
- **Los datos de la aplicación** (en `<application>`): icono, nombre, tema…

```xml
<?xml version="1.0" encoding="utf-8"?>
<manifest xmlns:android="http://schemas.android.com/apk/res/android">

    <uses-permission android:name="android.permission.INTERNET" />

    <application
        android:icon="@mipmap/ic_launcher"
        android:label="@string/app_name"
        android:theme="@style/Theme.MiApp">

        <activity android:name=".MainActivity" android:exported="true">
            <intent-filter>
                <action android:name="android.intent.action.MAIN" />
                <category android:name="android.intent.category.LAUNCHER" />
            </intent-filter>
        </activity>

    </application>
</manifest>
```

Detalles útiles:

- El `intent-filter` con `MAIN` y `LAUNCHER` indica cuál es la **actividad de entrada**: la que se abre al tocar el icono de la app.
- `.MainActivity` (con punto delante) es una forma abreviada: se completa con el `namespace` definido en el archivo `build.gradle` del módulo.
- `<manifest>` y `<application>` aparecen una sola vez, y `<application>` va dentro de `<manifest>`.
- Si usas filtros de intents, la actividad debe declarar `android:exported` (obligatorio desde Android 12).

## 6. Los recursos (`res/`)

Son todo lo que **no es código**: imágenes, textos, colores, diseños de pantalla, iconos… Mantenerlos separados del código permite adaptar la app a idiomas, tamaños de pantalla o modo oscuro sin tocar el Java.

| Carpeta | Qué contiene |
|---|---|
| `layout/` | Diseños de pantalla en XML (por ejemplo, `activity_main.xml`) |
| `drawable/` | Imágenes (PNG, JPG) y gráficos definidos en XML (formas, selectores…) |
| `mipmap/` | Iconos de la aplicación, en distintas densidades de pantalla |
| `values/` | Valores sencillos en XML: textos (`strings.xml`), colores, temas… |
| `font/` | Tipografías (TTF, OTF) |
| `raw/` | Archivos de cualquier tipo, que se leen tal cual (audio, por ejemplo) |
| `xml/` | Otros archivos XML de configuración |

Nunca se guardan archivos directamente dentro de `res/`: tienen que ir en una de sus subcarpetas.

### Cómo se usan los recursos

- **Desde Java:** con la clase generada `R`, escribiendo `R.tipo.nombre`. Por ejemplo, `R.layout.activity_main` o `R.string.saludo`. `R` se crea automáticamente al compilar.
- **Desde XML:** con la forma `@tipo/nombre`, como en `@string/app_name` o `@mipmap/ic_launcher`.

Ejemplo de `res/values/strings.xml`:

```xml
<resources>
    <string name="app_name">Mi App</string>
    <string name="saludo">¡Hola, mundo!</string>
</resources>
```

### Recursos alternativos

Android permite tener varias versiones de un mismo recurso y elige la adecuada según el dispositivo. Basta con añadir un **calificador** al nombre de la carpeta:

```
res/
├── values/          strings.xml   ← textos por defecto
├── values-es/       strings.xml   ← textos en español
├── drawable/        logo.png
├── drawable-night/  logo.png      ← versión para modo oscuro
└── drawable-hdpi/   logo.png      ← versión para pantallas de alta densidad
```

Conviene proporcionar siempre la versión **por defecto** (sin calificador); si no, la app puede fallar en dispositivos que no encajen con ninguna variante.

### `res/` frente a `assets/`

- Los archivos de **`res/`** reciben un identificador en la clase `R` y se leen a través de él.
- Los archivos de **`assets/`** no reciben identificador: se conservan con su nombre y estructura originales y se leen con `AssetManager`. Se usan, por ejemplo, para datos de un juego.

## 7. Gradle: la configuración de compilación (`Gradle Scripts`)

**Gradle** es el sistema que compila la aplicación: lee los archivos de configuración, descarga las bibliotecas que necesitas y genera el resultado en la carpeta `build/`.

| Archivo | Qué hace |
|---|---|
| `build.gradle(.kts)` del **módulo `app`** | Configuración de la app: identificador, versiones de Android, dependencias |
| `build.gradle(.kts)` del **proyecto** | Configuración común a todos los módulos |
| `settings.gradle(.kts)` | Indica qué módulos forman el proyecto |
| `gradle.properties` | Opciones generales de Gradle |
| `local.properties` | Ruta del SDK de Android en tu equipo. Es local: no se comparte |

> Los archivos pueden terminar en `.gradle` (lenguaje Groovy) o en `.gradle.kts` (lenguaje Kotlin). Los proyectos nuevos usan Kotlin por defecto, pero Groovy sigue siendo compatible. Aunque el script esté en Kotlin, tu aplicación sigue siendo Java.

Fragmento típico del archivo del módulo `app` (los números son solo un ejemplo):

```kotlin
android {
    namespace = "com.example.miapp"          // paquete base del código
    compileSdk = 36                          // versión de Android con la que se compila

    defaultConfig {
        applicationId = "com.example.miapp"  // identificador único de la app
        minSdk = 24                          // versión mínima de Android soportada
        targetSdk = 36                       // versión para la que se prepara la app
        versionCode = 1                      // número de versión (para Google Play)
        versionName = "1.0"                  // versión visible para el usuario
    }
}

dependencies {
    implementation("androidx.appcompat:appcompat:<versión>")   // bibliotecas que usa la app
}
```

Valores clave:

- **`namespace`:** paquete base del código; sirve para completar los nombres abreviados del manifiesto.
- **`applicationId`:** identificador único de la app en el dispositivo y en Google Play.
- **`minSdk` / `targetSdk`:** versión mínima soportada y versión para la que se prepara la app. Cuando usas Android Studio, conviene definirlos aquí y no en el manifiesto.
- **`dependencies`:** bibliotecas externas que la app necesita.

## 8. Cómo encaja todo

Al tocar el icono de la app ocurre esto:

1. El sistema lee el **manifiesto** y localiza la actividad marcada con `MAIN` y `LAUNCHER`.
2. Crea esa actividad (`MainActivity`, en `java/`) y ejecuta su método `onCreate()`.
3. `setContentView(R.layout.activity_main)` carga el diseño de la pantalla, que está en `res/layout/`.
4. Esa pantalla muestra textos, imágenes y colores tomados de `res/values/` y `res/drawable/`.

Y todo esto lo ha empaquetado y compilado **Gradle**, siguiendo lo que indican los archivos `build.gradle`.

## 9. Resumen

| Parte | Dónde está | Para qué sirve |
|---|---|---|
| Código | `java/` | La lógica de la app, en clases Java |
| Manifiesto | `AndroidManifest.xml` | Declara componentes, permisos y la actividad de entrada |
| Recursos | `res/` | Pantallas, textos, imágenes, colores, iconos |
| Assets | `assets/` | Archivos que se incluyen tal cual |
| Gradle | `build.gradle(.kts)` | Compila la app y gestiona versiones y dependencias |
| Pruebas | `test/` y `androidTest/` | Pruebas locales y pruebas en dispositivo |
| Resultado | `build/` | Archivos generados al compilar (no se editan) |
