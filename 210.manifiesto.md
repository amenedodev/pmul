# El manifiesto de Android (`AndroidManifest.xml`)

Toda aplicación Android necesita un archivo llamado exactamente `AndroidManifest.xml` en la raíz de su código fuente (en un proyecto de Android Studio, `app/src/main/AndroidManifest.xml`). En él se proporciona la información que Android necesita conocer de la aplicación para poder ejecutar su código. Solo son obligatorios los elementos `<manifest>` y `<application>`, y cada uno puede aparecer una única vez.

Se declaran tres tipos de información:

- **Componentes de la aplicación**:
  - actividades (`<activity>`)
  - servicios (`<service>`)
  - receptores de difusión (`<receiver>`, clase `BroadcastReceiver`)
  - proveedores de contenidos (`<provider>`, clase `ContentProvider`)

  Para cada componente se indica su clase y los *intents* con los que puede funcionar. Si una clase que hereda de uno de estos componentes no está declarada en el manifiesto, el sistema no puede iniciarla.
- **Permisos**: los que necesita la aplicación y los que deben tener otras aplicaciones para acceder a su contenido.
- **Requisitos del dispositivo**: características de hardware y software que necesita la aplicación. Determinan en qué dispositivos se puede instalar desde Google Play. Incluye el nivel mínimo de API de Android requerido y las bibliotecas con las que debe enlazarse.

## El paquete: `namespace` y `applicationId`

Antes, el paquete Java de la aplicación se declaraba en el atributo `package` del manifiesto. En los proyectos actuales con Gradle se define en `build.gradle` con dos propiedades distintas:

```kotlin
android {
    namespace = "com.example.myapp"          // paquete de las clases generadas (R, BuildConfig)
    defaultConfig {
        applicationId = "com.example.myapp"  // identificador único de la app en el dispositivo y en Google Play
    }
}
```

- El `namespace` se usa también para resolver los nombres de clase que empiezan por punto: `android:name=".MainActivity"` equivale a `com.example.myapp.MainActivity`. Para clases en subpaquetes hay que escribirlos (`.compras.PagoActivity`) o usar el nombre completo.
- El `applicationId` es lo que Google Play y Android usan para identificar la app. **Una vez publicada, no debe cambiarse nunca**: Google Play lo trataría como otra aplicación.
- Se recomienda que ambos coincidan. Si no se define `applicationId`, toma el valor del `namespace`.

## Estructura general

A continuación se muestran los elementos (sin atributos ni contenido). Hay dos reglas de orden: `<application>` debe ser el último elemento dentro de `<manifest>`, y cada `<activity-alias>` debe ir después de la `<activity>` a la que da alias.

```xml
<manifest>

    <uses-permission />
    <uses-permission-sdk-23 />
    <permission />
    <permission-tree />
    <permission-group />
    <instrumentation />

    <uses-sdk />
    <uses-configuration />
    <uses-feature />
    <supports-screens />
    <compatible-screens />
    <supports-gl-texture />
    <queries />

    <application>

        <activity>
            <intent-filter>
                <action />
                <category />
                <data />
            </intent-filter>
            <meta-data />
        </activity>

        <activity-alias>
            <intent-filter> … </intent-filter>
            <meta-data />
        </activity-alias>

        <service>
            <intent-filter> … </intent-filter>
            <meta-data />
        </service>

        <receiver>
            <intent-filter> … </intent-filter>
            <meta-data />
        </receiver>

        <provider>
            <grant-uri-permission />
            <meta-data />
            <path-permission />
        </provider>

        <uses-library />

    </application>

</manifest>
```

## Elementos de `<manifest>`

| Elemento | Para qué sirve |
|---|---|
| `<uses-permission>` | Permiso del sistema que necesita la aplicación (ver apartado de permisos). |
| `<uses-permission-sdk-23>` | Solicita un permiso solo en Android 6.0 (API 23) o superior. |
| `<permission>` | Declara un permiso propio, que permite limitar el acceso a componentes o funciones de la aplicación. |
| `<permission-tree>` | Declara el nombre base de un árbol de permisos. |
| `<permission-group>` | Declara el nombre de un grupo de permisos relacionados. |
| `<instrumentation>` | Declara una clase `Instrumentation` que permite monitorizar la interacción de la aplicación con el sistema (se usa en pruebas). |
| `<uses-sdk>` | Indica la compatibilidad con las versiones del sistema mediante el nivel de API (ver apartado de niveles de API). |
| `<uses-configuration>` | Indica qué características de entrada requiere la aplicación. |
| `<uses-feature>` | Declara una característica de hardware o software de la que depende la aplicación (ver apartado de requisitos de hardware). Se incluye un elemento por característica. |
| `<supports-screens>` | Indica qué tamaños de pantalla soporta la aplicación (pequeñas, normales, grandes, extra grandes o limitar por dp) y activa el modo de compatibilidad para pantallas mayores. |
| `<compatible-screens>` | Indica las combinaciones de tamaño y densidad de pantalla para las que la aplicación es compatible. Android nunca lee esta información: solo sirve para filtrar aplicaciones al usuario. Se recomienda no usarla y emplear mejor `<supports-screens>`. |
| `<supports-gl-texture>` | Declara que la aplicación soporta un formato concreto de compresión de texturas de OpenGL. |
| `<queries>` | Declara las otras aplicaciones a las que la aplicación necesita acceder (visibilidad de paquetes, necesaria desde Android 11). |


## Elementos de `<application>`

| Elemento | Para qué sirve |
|---|---|
| `<activity>` | Un elemento por cada actividad de la aplicación. |
| `<activity-alias>` | Declara un alias para una actividad. |
| `<service>` | Declara un servicio: componente sin interfaz que ejecuta alguna tarea en segundo plano. |
| `<receiver>` | Declara un `BroadcastReceiver`, que permite a la aplicación recibir *intents* enviados en modo difusión (*broadcast*). |
| `<provider>` | Declara un `ContentProvider`, que proporciona un acceso estructurado a los datos de la aplicación. |
| `<intent-filter>` | Indica los tipos de *intents* a los que puede responder un componente. Contiene `<action>`, `<category>` y `<data>`. |
| `<meta-data>` | Pareja nombre-valor con datos arbitrarios para el componente que la contiene. |
| `<grant-uri-permission>` | Indica los subconjuntos de datos de la aplicación a los que puede acceder el proveedor de contenidos. |
| `<path-permission>` | Define la ruta y los permisos necesarios para un subconjunto de los datos de un proveedor de contenidos. |
| `<uses-library>` | Especifica una biblioteca compartida con la que debe enlazarse la aplicación. |

### El atributo `android:exported`

Si la aplicación apunta a Android 12 (API 31) o superior, **toda actividad, servicio o receptor de difusión que use `<intent-filter>` debe declarar explícitamente `android:exported`**. Si falta, la aplicación no se puede instalar en dispositivos con Android 12 o superior. En Android Studio aparece como un aviso de *lint* y como un error de fusión del manifiesto.

- Con la categoría `LAUNCHER` (la actividad que abre el icono de la aplicación): `android:exported="true"`.
- En la mayoría de los demás casos: `android:exported="false"`, para que otras aplicaciones no puedan iniciar el componente.

## Ejemplo mínimo

```xml
<?xml version="1.0" encoding="utf-8"?>
<manifest xmlns:android="http://schemas.android.com/apk/res/android">

    <uses-permission android:name="android.permission.INTERNET" />
    <uses-feature android:name="android.hardware.camera" android:required="false" />

    <application
        android:icon="@mipmap/ic_launcher"
        android:label="@string/app_name"
        android:theme="@style/Theme.MiApp">

        <activity android:name=".MainActivity" android:exported="true">
            <intent-filter>
                <action android:name="android.intent.action.MAIN" />
                <category android:name="android.intent.category.LAUNCHER" />
            </intent-filter>
        </activity>

        <service android:name=".MiServicio" android:exported="false" />

    </application>
</manifest>
```

## Permisos (`<uses-permission>`)

Todos los permisos que necesita la aplicación deben declararse con `<uses-permission>`. Hay dos tipos principales:

- **Permisos normales** (como `INTERNET`): se conceden automáticamente al instalar la aplicación.
- **Permisos peligrosos** (como `CAMERA` o los de ubicación): desde Android 6.0 (API 23) no se aprueban en la instalación, sino que la aplicación debe pedirlos **en tiempo de ejecución**, y el usuario puede concederlos o revocarlos de forma individual.

## Niveles de API (`<uses-sdk>`)

El nivel de API es un número entero, distinto del número de versión de Android (por ejemplo, Android 16 es el API 36).

| Atributo | Significado |
|---|---|
| `android:minSdkVersion` | Nivel mínimo necesario para ejecutar la aplicación. El sistema impide instalarla en dispositivos con un nivel inferior. Conviene declararlo siempre: si se omite, vale 1. |
| `android:targetSdkVersion` | Nivel con el que se ha desarrollado y probado la aplicación. Si no se indica, vale lo mismo que `minSdkVersion`. Permite que el sistema no active comportamientos de compatibilidad para ese nivel. Se recomienda subirlo al último nivel y probar en esa plataforma. |
| `android:maxSdkVersion` | Nivel máximo para el que está diseñada la aplicación. **Google no recomienda declararlo**: no hace falta para bloquear versiones nuevas (son compatibles hacia atrás) y puede hacer que la aplicación desaparezca de un dispositivo tras actualizar el sistema. |

```xml
<uses-sdk android:minSdkVersion="24"
          android:targetSdkVersion="36" />
```

En Android Studio, estos valores se escriben en `build.gradle` (`minSdk` y `targetSdk` dentro de `defaultConfig`), y **sustituyen** a los del elemento `<uses-sdk>` del manifiesto.

### Requisito de Google Play

Según la [página de requisitos de Google](https://developer.android.com/google/play/requirements/target-sdk), desde el 31 de agosto de 2026 las aplicaciones nuevas y las actualizaciones deben apuntar al **API 36 (Android 16)** o superior. Hay excepciones: Wear OS y Android Automotive OS, API 35; Android TV y Android XR, API 34.

Las aplicaciones ya publicadas deben apuntar al API 35 o superior para seguir disponibles para usuarios nuevos en dispositivos con versiones de Android posteriores a su `targetSdkVersion`. Las que apuntan a un nivel inferior solo están disponibles en dispositivos con esa versión de Android o anterior.

## Requisitos de hardware y software (`<uses-feature>`)

Informa de los elementos de hardware o software de los que depende la aplicación. Se incluye **un elemento por característica**, con el nombre completo en `android:name`. Si la característica es opcional, se indica con `android:required`:

```xml
<uses-feature android:name="android.hardware.camera" android:required="false" />
```

- `android:required="true"` (valor por defecto): la aplicación no puede funcionar sin esa característica, y Google Play no la ofrece en dispositivos que no la tengan.
- `android:required="false"`: la aplicación usa la característica si existe, pero puede funcionar sin ella. Google Play no la oculta en dispositivos que no la tengan.

### Características implícitas por los permisos

Google Play deduce requisitos de hardware a partir de algunos permisos, aunque no haya un `<uses-feature>`. Si se declara de forma explícita con `required="false"`, esa declaración tiene prioridad y se desactiva el filtro implícito.

| Permiso | Característica implícita |
|---|---|
| `CAMERA` | `android.hardware.camera` y `android.hardware.camera.autofocus` |
| `RECORD_AUDIO` | `android.hardware.microphone` |
| `BLUETOOTH`, `BLUETOOTH_ADMIN` | `android.hardware.bluetooth` |
| `ACCESS_COARSE_LOCATION`, `ACCESS_FINE_LOCATION` | `android.hardware.location` |
| `CALL_PHONE`, `SEND_SMS`, `READ_SMS`... | `android.hardware.telephony` |
| `ACCESS_WIFI_STATE`, `CHANGE_WIFI_STATE` | `android.hardware.wifi` |

### Versión de OpenGL ES

También se puede exigir una versión de OpenGL ES con `android:glEsVersion`. Los 16 bits altos indican la versión principal y los 16 bajos la secundaria:

```xml
<uses-feature android:glEsVersion="0x00030002" android:required="true" />   <!-- OpenGL ES 3.2 -->
```

Solo puede haber un `glEsVersion` por manifiesto. Si no se declara, se asume OpenGL ES 1.0. Una plataforma que soporta una versión soporta todas las anteriores, así que basta declarar la más baja que se necesite y comprobar el resto en tiempo de ejecución.
