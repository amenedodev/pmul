# Tipos de aplicaciones móviles

Hay varias formas de desarrollar una aplicación móvil, y según la tecnología elegida se agrupan en cuatro tipos:

1. Aplicaciones nativas
2. Aplicaciones multiplataforma con código común
3. Aplicaciones web y PWA
4. Aplicaciones híbridas

## Aplicaciones nativas

Una aplicación nativa es la que se desarrolla y optimiza con el SDK específico de cada fabricante.

- **Android:** los lenguajes más adecuados hoy son **Kotlin** y **Java**. Google declaró Kotlin como lenguaje preferido para Android en 2019, y sus nuevas herramientas, como Jetpack Compose, se diseñan primero para Kotlin aunque Java sigue soportado.
- **iOS:** se programa en **Swift** (antes en Objective-C).

El entorno de desarrollo oficial para Android es [Android Studio](https://developer.android.com/studio), el IDE oficial de Google desde 2014.

En Android también es posible llamar a código nativo escrito en C o C++ mediante el **NDK** (*Native Development Kit*). Según [la propia documentación de Google](https://developer.android.com/ndk), el NDK no debe usarse solo por preferir ese lenguaje: aumenta la complejidad y la mayoría de las aplicaciones no notan mejora de rendimiento.

**Ventajas**

- Mejor rendimiento.
- Distribución a través de las tiendas de aplicaciones oficiales.
- Aprovechamiento de las características físicas del dispositivo (GPS, cámara, etc.).

**Inconvenientes**

- Hay que mantener un código distinto para cada sistema operativo.

## Aplicaciones multiplataforma con código común

Permiten escribir gran parte del código una sola vez y generar aplicaciones para varios sistemas operativos. Según la tecnología, la interfaz es nativa o la dibuja el propio framework.

| Tecnología | Lenguaje | Características |
|---|---|---|
| [Flutter](https://flutter.dev) | Dart | Creado por Google. Dibuja su propia interfaz en lugar de usar los componentes del sistema. |
| [React Native](https://reactnative.dev) | JavaScript / TypeScript | Creado por Meta. Usa componentes de interfaz nativos. |
| [Kotlin Multiplatform](https://kotlinlang.org/docs/multiplatform.html) | Kotlin | Comparte la lógica de negocio entre plataformas, y la interfaz puede ser nativa o compartida. |
| [.NET MAUI](https://learn.microsoft.com/dotnet/maui/) | C# | Sucesor de Xamarin. Genera aplicaciones para Android, iOS, Windows y macOS. |

### Nota sobre Xamarin

**Xamarin** fue durante años la opción más conocida de este grupo: permitía generar salida nativa para iOS, Android, Windows y macOS desde un mismo código C#. Fundada en 2011 por Miguel de Icaza (creador de Mono, la alternativa libre a .NET), la empresa fue adquirida por Microsoft en 2016. Microsoft terminó su soporte en mayo de 2024 y lo sustituyó por .NET MAUI.

**Ventajas**

- Un único código base para varias plataformas.
- Distribución a través de las tiendas oficiales.
- Acceso al hardware del dispositivo.

**Inconvenientes**

- Dependencia del framework y de su ritmo de actualizaciones.
- Para algunas funciones muy específicas de cada sistema hay que escribir código nativo.

## Aplicaciones web

Se desarrollan con HTML, CSS y JavaScript, por lo que funcionan en el navegador de cualquier sistema operativo y dispositivo (móvil, tableta, escritorio...). Suelen ser aplicaciones *responsive*, que se adaptan al tamaño de pantalla.

### PWA (Progressive Web Apps)

Las **PWA** son aplicaciones web que añaden capacidades propias de una aplicación instalada:

- Se pueden **instalar** en la pantalla de inicio.
- Funcionan **sin conexión** o con conexión limitada gracias a los *service workers*.
- Pueden enviar notificaciones y acceder a parte del hardware (geolocalización, cámara...), con diferencias según el navegador y el sistema operativo.

**Ventajas**

- Un único desarrollo para todas las plataformas.
- Sin instalación (o instalación opcional desde el navegador).
- Actualización inmediata, sin pasar por las tiendas.

**Inconvenientes**

- Acceso limitado a las características físicas del dispositivo, que varía según el sistema y el navegador.
- Interfaz menos cómoda y menos integrada con el sistema que una aplicación nativa.
- Una aplicación web convencional necesita conexión a internet; una PWA bien diseñada puede funcionar sin ella, pero con funciones limitadas.

## Aplicaciones híbridas

Combinan aspectos de las aplicaciones nativas y de las web. Se programan con estándares web (HTML5, CSS y JavaScript) y se ejecutan dentro de un contenedor nativo (un *WebView*), desde el que se accede a elementos del dispositivo como el GPS, la cámara o los contactos.

**Ventajas**

- Distribución a través de las tiendas de aplicaciones oficiales.
- Gran parte del código es compartido.
- Acceso a buena parte del hardware del dispositivo.

**Inconvenientes**

- Visualmente se parece más a una web que a una aplicación nativa.
- El rendimiento suele ser inferior al de una aplicación nativa.

### Herramientas

Existen múltiples plataformas para programar aplicaciones híbridas. Una de las más conocidas es [Ionic](https://ionicframework.com), que se compone de:

- **Un framework web para la interfaz.** Ionic funciona con [Angular](https://angular.dev), React o Vue. Angular es un framework basado en componentes y escrito en TypeScript; no debe confundirse con el antiguo AngularJS, que es otro producto y dejó de recibir soporte en enero de 2022.
- **Un contenedor nativo** donde se ejecuta la parte web de la aplicación:
  - [Capacitor](https://capacitorjs.com), el contenedor actual del ecosistema Ionic, que se usa por defecto en proyectos nuevos.
  - [Apache Cordova](https://cordova.apache.org), la alternativa anterior, que es la versión de código abierto de PhoneGap. Adobe discontinuó PhoneGap en 2020, pero Cordova sigue existiendo.

## Resumen comparativo

| Tipo | Código | Rendimiento | Acceso al hardware | Tiendas oficiales | Ejemplos |
|---|---|---|---|---|---|
| Nativa | Uno por sistema | Muy alto | Completo | Sí | Kotlin/Java, Swift |
| Multiplataforma | Mayoritariamente común | Alto | Casi completo | Sí | Flutter, React Native, Kotlin Multiplatform, .NET MAUI |
| Web / PWA | Único | Medio | Limitado | No (las PWA pueden publicarse en algunas) | HTML + CSS + JavaScript |
| Híbrida | Mayoritariamente común | Medio | Amplio, mediante plugins | Sí | Ionic con Capacitor o Cordova |
