# Evolución del runtime de Android: Dalvik, ART y la compilación JIT/AOT

Las aplicaciones Android no se ejecutan sobre una máquina virtual Java (JVM) estándar, sino sobre una máquina virtual propia, diseñada para dispositivos con recursos limitados y para reducir el consumo de energía. Cada aplicación se ejecuta en su propio proceso, con su propia instancia de esa máquina virtual.

## Del código fuente al formato DEX

El código Java o Kotlin se compila primero a archivos `.class` (bytecode Java). Después, la herramienta D8 (originalmente era **dx**), que los convierte a un único formato propio de Android, el **DEX**. Además, **R8** reduce y ofusca el código al construir la aplicación.

**DEX** (*Dalvik Executable Format*) es un bytecode genérico, que no depende de ningún dispositivo concreto. Por eso hay que traducirlo al código máquina del dispositivo (interpretándolo o compilándolo) antes de ejecutarlo.

## De Dalvik a ART

Originalmente la máquina virtual era **DVM** (*Dalvik Virtual Machine*).

A partir de la versión 5.0 (Lollipop) pasó a ser **ART** (*Android Runtime*), que ya se podía elegir como opción en KitKat (4.4). Las aplicaciones desarrolladas para Dalvik se ejecutan correctamente en ART, porque ambos usan el formato DEX.

La diferencia básica entre Dalvik y ART está en cómo se compilan las aplicaciones: Dalvik usa JIT y ART usa AOT (en su diseño original).

### Compilación JIT (Just In Time) en Dalvik

- La herramienta **dexopt** genera un archivo **ODEX** (*Optimized DEX*), que no es código nativo, sino un DEX verificado y optimizado. Se genera una sola vez, al instalar la aplicación o la primera vez que se ejecuta.
- El código que se usa con frecuencia se compila a código máquina **durante la ejecución**, en memoria, en cada ejecución de la aplicación. Esta compilación JIT se incorporó en Android 2.2.

### Compilación AOT (Ahead Of Time) en ART

La herramienta **dex2oat** genera, una única vez en la instalación, un archivo **OAT** (basado en el formato **ELF**, *Executable and Linkable Format*) con el código máquina de la aplicación. Se usa siempre a partir de entonces, en ese dispositivo.

## Ventajas e inconvenientes

| | JIT (Dalvik) | AOT (ART en Android 5.0 y 6.0) |
|---|---|---|
| Instalación | Más rápida | Más lenta |
| Espacio ocupado | Menos | Más |
| Velocidad de ejecución | Más lenta | Más rápida |
| Consumo de CPU y energía al ejecutar | Mayor (compila mientras se ejecuta) | Menor (el código ya está compilado) |

## ART en las versiones actuales

Desde **Android 7.0 (Nougat)**, ART combina las dos técnicas para evitar los inconvenientes de la compilación AOT completa:

1. La aplicación se instala rápidamente, sin compilarla entera.
2. Al principio se ejecuta interpretándola y con compilación JIT, y se registra un **perfil** del código que más se usa.
3. Cuando el dispositivo está inactivo y cargando, ART compila con AOT solo ese código frecuente.

El resultado es una instalación rápida, menos espacio ocupado y el rendimiento de AOT donde más importa. Los desarrolladores pueden incluso distribuir perfiles ya preparados con la aplicación.
